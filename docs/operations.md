# Эксплуатация, стоимость и восстановление

VPS обслуживает метаданные и доступ к библиотеке. Компьютер выполняет тяжёлую
обработку, а S3 принимает и выдаёт медиа. Эти части можно обновлять и восстанавливать
независимо, если сохраняются версии API и ссылки между объектами.

## Текущее состояние и будущий запуск

Сейчас репозиторий содержит только документацию. API, приложения, контейнеры,
миграции, установщики и рабочие интеграции отсутствуют. Команды `docker compose up`
или `flutter run` пока не являются инструкцией запуска проекта.

Для чтения решения достаточно клонировать репозиторий и открыть README.
Документы отображаются на GitHub. Их копия размещается в закрытом personal-docs
по общему стандарту. Публикация документации не разворачивает приложение.

Перед первым запуском нужно реализовать и проверить клиент, API, миграции,
веб-плеер и обработчик. Только затем создаются окружение, закрытый бакет,
учётная запись владельца и резервирование. Реальные адреса, имена бакетов,
учётные записи и секреты хранятся вне Git.

## План размещения

Для первой версии предлагается один VPS: TLS reverse proxy, Go API и PostgreSQL
через Docker Compose. PostgreSQL не доступен из интернета. Отдельная GPU или
установка моделей на VPS не требуется. Начальная оценка 2 vCPU и 2–4 ГиБ RAM
является ориентиром для замеров, а не подтверждённым размером сервера.

Reverse proxy принимает только ограниченный JSON и статические файлы плеера.
Загрузка бинарных тел медиа отклоняется. Кеширование S3 через reverse proxy,
буферизация записей на его диске и запись их тел в логи не разрешены.

S3 использует стандартный класс для активных записей. Начинаем без CDN и адаптивных
многовариантных потоков. Они добавляются при измеримой проблеме доставки, с отдельным
расчётом стоимости. Политики CORS разрешают нужные операции браузерному плееру,
но не заменяют проверку доступа к объектам.

На Mac и Windows модели загружаются пользователем один раз, с проверкой хеша,
версии и лицензии. Нативные библиотеки поставляются из воспроизводимых сборок.
Окончательные SDK, драйверы, версии ОС и требования к установке определяются
проверкой совместимости, включая CUDA для выбранной видеокарты.

## Конфигурация

| Где | Настройки | Способ хранения |
| --- | --- | --- |
| VPS | Подключение PostgreSQL, S3 endpoint и bucket, credentials, ключи сессий | Закрытое окружение сервиса, вне репозитория |
| Клиент | API base URL, ID устройства, токены, лимит кеша | Настройки приложения и системное хранилище секретов |
| Обработчик | Пути runtime и моделей, хеши, GPU-профиль, лимит временного диска | Локальная конфигурация пользователя |
| Веб-плеер | Публичный API base URL | Публичная конфигурация без постоянных ключей |

Точные имена переменных будут частью первого реализованного контракта конфигурации.
Публичный репозиторий не содержит рабочих `.env`, дампов, записей или моделей.

## Учёт хранения и трафика

Стоимость состоит из VPS, занятого места S3, операций, исходящего трафика и
дополнительных копий. Считается весь объём: оригиналы, версии просмотра,
экспортированные фрагменты, старые версии и резервные копии.

Для предварительной оценки на 2026-11-07 используем ставки из официальных примеров:
стандартное хранение 2,376 ₽ за тарифицируемый ГБ в месяц, исходящий трафик после
первых 100 ГБ по 1,67994 ₽/ГБ в пределах следующего диапазона. Первый 1 ГБ хранения
бесплатен. Это расчётный ориентир, не зафиксированное коммерческое предложение:
актуальный тариф нужно сверить перед оплатой. [Тарификация Object Storage](https://yandex.cloud/ru/docs/storage/pricing).

Например, 100 ГБ суммарных объектов и 300 ГБ исходящего трафика дают
`99 × 2,376 + 200 × 1,67994 ≈ 571,21 ₽/мес`, без VPS и платных операций.
Повторный просмотр на другом устройстве и скачивание обработчиком тоже могут
создавать исходящий трафик. Количество файлов не заменяет измерение байтов.

Интерфейс должен показывать объём оригиналов, производных объектов и локального
кеша отдельно. Уведомления бюджета не считаются жёстким запретом расходов.
Ограничение частоты выдачи ссылок снижает злоупотребления, но не гарантирует
точный денежный лимит прямого S3-трафика.

## Резервирование и удаление

Предлагается ежедневная зашифрованная резервная копия PostgreSQL с отдельными
учётными данными, вне диска VPS, и регулярная проверка восстановления. Первые
проектные цели: потеря подтверждённых метаданных не более 24 часов и восстановление
в пределах одного рабочего дня. Они должны быть подтверждены учебным восстановлением.

Для оригиналов нужна независимая копия в другом месте либо отдельном аккаунте.
Версионирование S3 помогает при перезаписи и ошибочном удалении, но не заменяет
независимый backup. Конкретное место независимой копии выбирается перед загрузкой
уникальных материалов. Производные версии и индексы обычно можно восстановить,
но срок их пересоздания зависит от включённого компьютера.

Восстановление начинается с PostgreSQL, затем проверяет наличие всех объектов,
на которые ссылаются активные материалы и публикации. Объекты без ссылок не удаляются
до завершения сверки. Очистка после восстановления отключена до ручного подтверждения
результата. Наличие backup-файла не считается доказательством восстановимости.

## Наблюдение и типовые сбои

API показывает состояние БД, очереди, задержку синхронизации и ошибки доступа к S3.
Обработчик показывает текущий этап, оставшиеся задания, доступный диск и ошибку
движка. Логи содержат request ID, коды ошибок и технические ID без текстов,
имён файлов владельца, токенов и подписанных URL.

При просроченной ссылке плеер получает новую и возвращается к прежней позиции.
При нехватке диска обработка приостанавливается. При потере аренды старый результат
не принимается. При недоступности сервера очередь правок остаётся локально.
При повреждении индекса он перестраивается из текстов, без удаления outbox.

## Обновления и канон документации

Перед изменением серверной схемы выполняется backup и проверяется совместимость
предыдущего клиента. Сначала применяется совместимое расширение контракта,
затем обновляются клиенты, и только после этого удаляются старые поля.
Откат бинарника не откатывает БД автоматически.

Технические документы в `docs/` определяют целевое решение. Их полная читательская
копия поддерживается в `personal-docs/src/content/docs/personal/media-knowledge/`.
Изменение решения обновляет обе версии, каталог, навигацию и карточку контекста.
Фактический запуск, подключённые интеграции и ограничения добавляются только после
проверки реализации. Реальные адреса закрытого портала в эти тексты не включаются.

Следующий шаг описан в [плане реализации](delivery.md).
