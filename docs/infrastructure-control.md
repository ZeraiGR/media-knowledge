# Контроль инфраструктуры

На 12 ноября 2026 года подтверждены автоматическая внешняя копия PostgreSQL,
независимая проверка Mac, действующие серверные выпуски и изолированный откат.
Первый этап остаётся открытым: нужны установки Android и Windows, испытание
уведомления о следующем настоящем выпуске на устройствах и наблюдение первого
еженедельного запуска восстановления. Прикладные этапы ещё не начаты.

## PostgreSQL и независимая копия

Первый автоматический ежедневный запуск подтверждён связкой systemd:
`LastTriggerUSec` таймера и старт службы совпали в `2026-11-12 02:19:04 UTC`.
Служба завершилась в `02:19:42 UTC` с кодом 0. Во внешнем репозитории зарегистрирован
snapshot `17533e95…`, созданный в `02:19:14 UTC`. Сохранённых failure-статусов
при чтении состояния не обнаружено. Ручной backup для этого доказательства
не запускался.

Mac самостоятельно прочитал этот snapshot в `08:31:27 UTC` по ежедневному
расписанию 11:30 по Москве. launchd показал два запуска и последний код 0.
Повторная независимая проверка в `18:13:41 UTC` подтвердила четыре файла,
ID репозитория и SHA-256 без обращения к VPS. Возраст копии составлял около
16 часов и укладывался в ограничение 26 часов.

В `18:21:08 UTC` вручную проверено восстановление именно новой автоматической
копии в изолированном PostgreSQL. Прикладных таблиц пока нет. Ранее выполненный
drill с 257 синтетическими строками остаётся отдельным доказательством
восстановления непустой БД, он не выдаётся за новую проверку.

Оба таймера активны и persistent. Следующая ежедневная копия назначена на
13 ноября около `02:20 UTC`, первый еженедельный запуск на 15 ноября около
`04:15 UTC`. Еженедельный автоматический запуск ещё не произошёл. Ручное
восстановление не заменяет его. Условия и ключи описаны в
[резервировании PostgreSQL](database-backup.md).

## Возврат предыдущего выпуска

Приёмник теперь проверяет код возврата запуска прежнего контейнера и его
readiness. Сообщение rollback ready появляется только после успешной проверки.
Неудачный выпуск всё равно завершается ошибкой, даже если прежняя версия
восстановлена. Ошибка восстановления также не скрывается.

На VPS выполнен `tests/drill_deploy.py` с отдельным Compose-проектом,
синтетическим PostgreSQL и случайным loopback-портом. Сначала запущен настоящий
образ API. Затем в тестовый слот передан локальный веб-образ, в котором нет
необходимого `/api`, что намеренно вызывает ошибку старта. Фактический приёмник
вернул прежний digest, восстановил images.env, запустил API и дождался `/readyz`.
Тестовые контейнеры, сеть и volume удалены. Рабочие ресурсы не использовались.

В этом drill подменены только операции login/pull и имя репозитория кандидата:
образы уже присутствовали локально. Работа Docker Compose и HTTP readiness
проверялась фактически. Доступ к GHCR проверяется существующим CI/CD отдельно.
Регрессионные unit-тесты покрывают таймаут кандидата и ошибку readiness отката.
Проверенный приёмник установлен на VPS без перезапуска рабочих контейнеров.

Живой откат рабочего выпуска не выполнялся. Откат контейнера не восстанавливает
данные БД. Полное восстановление нового VPS также не испытывалось.

## Установщики и устройства

Все три пакета существующего клиента `v0.1.0` скачаны из GitHub Releases.
Размеры и SHA-256 совпали одновременно с update-manifest.json и SHA256SUMS.
Код клиента прочитал живой feed, предложил этот выпуск для условной версии
`0.0.0` на Android, macOS и Windows, не предложил его для текущей `0.1.0`
и не нашёл установщик iOS. Это программная проверка на Mac, без фиктивного
публичного выпуска. Четыре существующих Flutter-теста и analyze прошли.

На реальном Mac установлен DMG выпуска `0.1.0` в пользовательский Applications.
Приложение запущено, интерфейс показал «Новых версий пока нет». Это подтверждает
установку и проверку текущего выпуска. Уведомление о следующей версии и переход
по кнопке из установленного приложения ещё не проверены. Подключение API через
интерфейс установленного Mac-клиента также не подтверждено.

Android-устройство не подключено. Доступный инструмент удалённого Windows
возвращает ошибку SSH с кодом 255, поэтому установка там не выполнена.
Flutter devices перечислил только реальный Mac и Chrome. Эмуляция не
использовалась и не считается установкой на телефон. Apple Developer отсутствует,
устанавливаемого IPA и распространения iOS нет.

## Условия перехода к большим медиа

До полного закрытия первого этапа остаются: наблюдение воскресного таймера,
установка APK на реальный Android, установка Windows-пакета при восстановлении
доступа, а также уведомление и загрузка следующего настоящего выпуска
из установленного клиента. Исправление двух старых состояний GitHub требует
доступного действия со стороны GitHub; текущие выпуски ими не заблокированы.

Серверная инфраструктура пригодна для изолированных испытаний, но весь этап
по критериям плана ещё не принят. Плеер, модели и медиатека в рамках этой работы
не реализуются. Объём S3, порог уведомления 500 ₽ и область резервирования БД
сохранены.
