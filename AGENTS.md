# Работа с Media Knowledge

Прочитать README и относящиеся к задаче документы в `docs/`.
Техническое решение описывает целевое поведение. Пока runtime не реализован,
не называть архитектурные решения проверенными интеграциями.

Для кода использовать Serena с активацией абсолютного пути текущего checkout.
Следовать `project-docs` и стандарту личного портала. Обновлять
`personal-docs/src/content/docs/personal/media-knowledge/` при изменении поведения,
архитектуры, контрактов, данных или эксплуатации. В начале продолжения прочитать
карточку Media Knowledge и активную итерацию в `personal-context`.

Согласованная граница: VPS не хранит и не проксирует видео и аудио, включая
временные файлы и тела запросов. Загрузка, скачивание и просмотр идут прямо в S3.
Транскрипция и языковые модели работают на компьютере владельца.

Личные данные, модели и секреты хранить вне исходников. Использовать синтетические
медиа для проверок. Не публиковать материалы владельца без отдельного поручения.
Добавлять только относящиеся к задаче изменения, сохранять чужой diff.

В описаниях PR объяснять проблему и итоговое поведение. Не добавлять разделы
тестирования, команды проверок и отчёты об их успешном прохождении.

Точные версии зависимостей, модели, ограничения ОС и сборки нативных библиотек
фиксировать после проверки совместимости. До замеров не обещать скорость
воспроизведения, качество транскрипции или объём памяти.
